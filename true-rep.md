## 1. Project Overview

### Vision

TrueRep is a subscription-based calisthenics training platform where multiple trainers create structured workout routines (beginner, intermediate, advanced) for users. Users subscribe to access daily workouts, track progress through gamification, compete in community challenges, and optionally pay for personalized training. The differentiation: social competition (leaderboards, group challenges), video technique library, and AI-powered posture feedback for form correction.

The platform serves two audiences: **End Users** (training clients) who access workouts, track progress, and compete; and **Trainers** (coaches) who create and manage routines. It's cross-platform (iOS, Android) to maximize accessibility.

### Goals

- Launch MVP on iOS + Android within 5 weeks
- Support multiple trainers with publicly shared routines (3 difficulty levels)
- Implement subscription monetization (monthly, annual) with Stripe
- Build gamification system to drive daily engagement (badges, XP, streaks, leaderboards)
- Enable social competition (public retos/challenges, real-time leaderboards)
- Support video feedback mechanism (upload → AI analysis) for form correction
- Achieve production-ready stability for launch (error handling, monitoring, CI/CD)

### Success Metrics

- First-week retention: >40% DAU
- Subscription conversion: >8% of signups → paid
- Posture feedback feature: >70% user satisfaction
- API uptime: >99%
- iOS + Android launch simultaneous (no staged rollout delays)

## 2. Tech Stack

| Layer | Technology | Why |
|-------|-----------|-----|
| **Mobile App** (iOS/Android) | React Native + Expo | Shared codebase for both platforms, rapid iteration, no XCode/Android Studio config, OTA updates |
| **Backend Framework** | Node.js + Next.js 15 | API routes, webhooks, admin dashboard in single codebase, fast iteration |
| **Language** | TypeScript | Type safety, better DX, catches bugs early |
| **Database** | PostgreSQL (Supabase) | Built-in auth, real-time subscriptions, storage for videos, role-based access |
| **ORM** | Prisma | Type-safe queries, migrations, auto-generated types from schema |
| **Auth** | Clerk | Native React Native support, OAuth, social login, managed sessions |
| **Payments** | Stripe | Clerk integrates directly, webhooks for subscription events, no PCI burden |
| **Video Hosting** | Cloudinary | Transformation, streaming, on-demand encoding, APIs for uploads |
| **AI Posture Analysis** | OpenAI Vision API | Analyzes uploaded video frames for exercise form (MVP: async, not real-time) |
| **Real-time** | Supabase Realtime | Leaderboard updates, challenge notifications, social feeds |
| **Hosting Backend** | Vercel | Serverless, auto-scaling, webhook delivery guarantees, preview deploys |
| **Mobile Distribution** | iOS App Store + Google Play | Via Expo EAS Build, later transition to native CI/CD |
| **Package Manager** | pnpm | Fast, efficient workspace management for monorepo (backend + shared utils) |

## 5. API Design

### Routes Overview

| Method | Path | Description | Auth | Notes |
|--------|------|-------------|------|-------|
| GET | `/api/health` | Liveness check | None | For monitoring |
| **Auth** | | | | |
| POST | `/api/auth/[...auth]` | Clerk webhooks | Clerk | Auto-sync user to DB |
| **Routines** | | | | |
| GET | `/api/routines` | List all public routines, filter by difficulty | None | Pagination: ?limit=10&offset=0 |
| POST | `/api/routines` | Create routine (trainer only) | User (Trainer) | Request body: {title, description, difficulty, duration_minutes, exercises, preview_video_url} |
| GET | `/api/routines/[id]` | Get routine details + exercises | None | Public |
| PATCH | `/api/routines/[id]` | Update routine (trainer only) | User (Trainer) | Only trainer who created it |
| DELETE | `/api/routines/[id]` | Delete routine (trainer only) | User (Trainer) | Soft delete preferred |
| **Workouts** | | | | |
| GET | `/api/workouts` | User's workout history | User | ?limit=10&offset=0, ordered desc by date |
| POST | `/api/workouts/log` | Log workout completion | User | Request: {routine_id, duration_minutes, exercises_completed, notes} |
| POST | `/api/workouts/[id]/feedback` | Fetch AI feedback for a workout | User | Async job status check |
| **Users** | | | | |
| GET | `/api/users/me` | Current user profile | User | Returns full user object + subscription |
| PATCH | `/api/users/me` | Update profile | User | Fields: username, avatar_url |
| GET | `/api/users/[id]/achievements` | User's badges | None | Public achievement list |
| GET | `/api/users/[id]/leaderboard-rank` | User's rank globally | None | Public rank + XP |
| **Subscriptions** | | | | |
| GET | `/api/users/subscriptions/current` | Active subscription details | User | Plan, expiry, status |

## 8. Authentication & Authorization

### Auth Flow

1. **Sign-up (new user)**
   - Opens Clerk sign-up modal (email or social OAuth)
   - Clerk creates session token
   - Backend receives Clerk webhook → creates `User` row in DB
   - Redirect to onboarding (choose role: user or trainer, set username)

2. **Login (returning user)**
   - Clerk handles auth → mobile app gets session token via `getToken()`
   - All API requests include `Authorization: Bearer {token}`
   - Backend validates token via Clerk SDK

3. **Onboarding**
   - Post-signup: collect username, avatar, role choice (user or trainer)
   - If trainer: unlock routine creation dashboard

4. **Session Management**
   - Mobile: Clerk SDK handles token refresh (expires in 1 hour)
   - Backend: Validates token on every request via Clerk's `auth()` middleware
   - Logout: Clear session locally, redirect to login

### Protected Routes

| Route | Public? | Requires Auth? | Requires Trainer? |
|-------|---------|---|---|
| `/api/routines` GET | ✅ Yes | ❌ No | ❌ No |
| `/api/routines` POST | ❌ No | ✅ Yes | ✅ Yes |
| `/api/workouts` | ❌ No | ✅ Yes | ❌ No |
| `/api/challenges` GET | ✅ Yes | ❌ No | ❌ No |
| `/api/challenges` POST | ❌ No | ✅ Yes | ✅ Yes |
| `/api/video-feedback/*` | ❌ No | ✅ Yes | ❌ No |
| `/api/users/me` | ❌ No | ✅ Yes | ❌ No |
| `/(app)/*` (mobile tabs) | ❌ No | ✅ Yes | ❌ No |

### Roles & Permissions

| Role | Capabilities |
|------|--------------|
| **User** | Browse public routines, log workouts, join challenges, upload videos for feedback, view profile, manage subscription |
| **Trainer** | All User capabilities + create/edit/delete routines, create challenges, view analytics (trainer dashboard) |
| **Admin** (future) | Moderation, suspension, analytics |

### Session Management

- **Mobile:** Clerk React Native SDK stores session in secure storage, auto-refreshes
- **Backend:** `getAuth()` from Clerk middleware extracts `userId` from request
- **Token Refresh:** Automatic, transparent
- **CORS:** Configured for mobile app domain + web admin

## 12. Deployment Strategy

- **Cost:** Free tier supports MVP (500MB storage, 6k function invocations/day; plenty for <5k users)
- **Setup:**
  1. Connect GitHub repo to Vercel
  2. Set environment variables (see section 10)
  3. Select `apps/backend` as root directory
  4. Deploy → auto-deploys on git push
  5. Custom domain: add DNS CNAME

**Mobile: iOS App Store & Google Play Store**
- **Why:** Distribution channel, mandatory for public launch
- **Process:**
  1. Build via EAS: `eas build --platform ios` and `eas build --platform android`
  2. Submit to stores (see Build Order, Step 34)
  3. App Store Connect and Google Play Console manage metadata, screenshots, version releases

**Database: Supabase (PostgreSQL)**
- **Why:** Managed PostgreSQL, built-in auth, real-time subscriptions, auto-backups
- **Cost:** Free tier: 500MB (enough for MVP), $25/mo for 8GB
- **Backups:** Auto-enabled, 7-day retention on free tier

**Media: Cloudinary**
- **Why:** Video/image storage, transformations, CDN delivery
- **Cost:** Free tier: 25 credits/month (enough for <1k video uploads/month)
- **Alternatives:** Supabase Storage (free, 1GB), AWS S3 (pay-as-you-go)

### CI/CD

**GitHub Actions (Optional, but Recommended)**
- Lint + type-check on every PR: `pnpm lint`
- Run tests before merge
- Auto-deploy main to Vercel

name: CI

      - run: pnpm type-check

## Architecture

### Directory Structure
- `apps/backend/src/app/` — Next.js App Router pages + API routes
- `apps/backend/src/lib/` — Database client, validators, external service wrappers
- `apps/mobile/src/app/` — Expo Router screens (auth stack + tab navigator)
- `apps/mobile/src/lib/` — API client, Clerk session, stores, hooks
- `apps/mobile/src/components/` — Reusable UI components

### Data Flow
1. Mobile app → API request (with Clerk auth token)
2. Backend middleware validates token via Clerk
3. Prisma ORM queries/mutates PostgreSQL
4. Response returned to mobile
5. React Query caches data + invalidates on mutations
6. Real-time updates via Supabase subscriptions (leaderboards, challenges)

### Key Patterns
- **Server Components by default** (backend) — only "use client" for interactivity
- **Middleware auth** — all `/(app)/*` routes protected by `middleware.ts`
- **Webhook safety** — Stripe webhook signature verified in handler
- **Error handling** — Zod validation at route entry, try-catch for external APIs, error boundaries in mobile
- **Real-time** — Supabase channels for leaderboards, challenge updates
- **State:** Zustand for mobile app state (user, active workout), React Query for server state

## Code Organization Rules

1. **Components:** One component per file, max 300 lines. Extract sub-components if longer.
2. **Imports:** Use path alias `@/` for `src/` imports. No barrel exports (import directly from source).
3. **API routes:** Validate input with Zod at route entry, return consistent JSON shape `{ data, error, status }`.
4. **Database:** All queries through Prisma client in `lib/db.ts`.
5. **Auth:** All protected routes check Clerk auth via middleware or route-level `auth()` call.
6. **Mobile forms:** Use React Hook Form + Zod for validation, no inline form state.
7. **Real-time:** Supabase subscriptions only on mobile, not Web.
